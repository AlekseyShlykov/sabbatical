# Методология: визуальная новелла из Twine (логика движка)

Этот файл описывает **архитектуру и соглашения**, без привязки к конкретному сюжету или ассетам. Его можно положить в новый репозиторий и воспроизвести ту же логику: экспорт из Twine → JSON → игра в браузере.

## Стек и роль файлов

- **Статическая вёрстка**: один `index.html`, стили в отдельном CSS, без сборщика (удобно для GitHub Pages).
- **Модули ES**: загрузка данных, разбор истории, движок диалога, локализация UI — разные файлы, чтобы не смешивать парсинг Twine и отрисовку.
- **Данные**:
  - JSON с историей (по одному файлу на язык или один общий — на ваш выбор).
  - Отдельные JSON со **строками интерфейса** (кнопки, подписи, ошибки) — **не** смешивать их с текстом сюжета.

Идея разделения: **сюжет** живёт в экспорте Twine, **оболочка приложения** — в словарях локали.

## Как писать текст в Twine перед экспортом (рабочий договор)

Это тот стиль, под который заточен движок: так вы кладёте готовые строки в тело пассажа, потом скидываете JSON в игру.

1. **Сначала всегда указываете, кто говорит** — одной строкой, в начале технический идентификатор и двоеточие, затем реплика (имя персонажа **не** дублируете внутри фразы — его не показывают в колонке текста):
   - `alien1: сказал это` или `Alien1: Сказал это` — левый персонаж;
   - `alien2: …` — правый.
   Регистр у идентификатора обычно не важен; важно **двоеточие сразу после метки говорящего**.

2. **Команды для движка** — **отдельной строкой**, целиком в виде **`//что сделать`** (строка **начинается** с `//`, дальше без переноса ваше описание действия в свободной форме, которое распознаёт обработчик в коде: фон, персонажи на сцене, музыка, флаги и т.д.). Примеры: `//фон космос`, `//показать alien2`, `//включи музыку`. Эта строка в диалоге **не появляется** и **не печатается**.

3. **Одна реплика на экране** — как в текущей реализации: в пассаже может быть много строк подряд, но игрок **в каждый момент видит только одну** реплику (один «кадр» текста); следующая — после кнопки **«Дальше»** (если в этом же пассаже ещё есть реплики) или сразу кнопки выбора / конец, если реплик больше нет. Это не лента чата из нескольких пузырей сразу.

Пример начала пассажа:

```
//фон мостик
//показать alien1
//показать alien2
alien1: Мы на месте.
alien2: Сканирую сектор.
```

Фон — `мостик.png` / `мостик.jpg`, портреты — `alien1.png`, `alien2.png`. Пока не выполнены команды `//показать`, соответствующие персонажи на сцене не видны.

## Поток: Twine → JSON → внутренний граф

1. В Twine пишется история как набор **пассажей** со связями.
2. Экспортируется JSON в согласованном формате (например «Twine to JSON»): у каждого пассажа есть **имя**, **текст тела** и массив **ссылок** с подписью кнопки и именем целевого пассажа.
3. **Первый пассаж в массиве** считается стартом (или явное имя вроде `Start`, если вы так договорились в коде).
4. Загрузчик превращает сырой JSON в **внутреннюю структуру**: словарь пассажей, у каждого — упорядоченный список **шагов** (реплики и служебные команды) и список **выборов** для перехода в другие пассажи.

Движок дальше работает только с этим графом, ему всё равно, Twine это или ручной JSON.

## Правила текста внутри пассажа

### Префиксы говорящих

- В авторской практике удобно вести реплики так: **`alien1: …`** / **`alien2: …`** (или `Alien1:` / `Alien2:`) — **сначала метка говорящего, потом двоеточие, потом текст**. Это и есть машиночитаемый префикс для двух героев слева и справа.
- Любые другие строки вида **`ЧтоУгодно: …`** (одно слово-идентификатор, двоеточие, текст) парсер может отнести к произвольному «говорящему» по правилам кода; для двух основных портретов на сцене закреплены именно **alien1** / **alien2**.
- В колонке диалога показывается **только текст после двоеточия**; имя в тексте реплики **не дублировать** — кто говорит, видно по подсветке портретов и стилю строки.
- Строка **без** префикса `Кто-то:` трактуется как **рассказчик** (отдельный визуальный стиль: курсив, приглушённый цвет).

### Одна реплика — одна строка (в исходнике)

- Каждая непустая строка тела пассажа после разбора становится отдельным шагом.
- **Пустые строки** в исходнике можно использовать как разделители смыслов в Twine, но в типичной схеме **одна реплика = одна строка** с префиксом.

### Несколько абзацев в одной реплике

Если в одном блоке после префикса два абзаца, разделённые пустой строкой, парсер может разбить это на **несколько последовательных шагов одного говорящего** — каждый показывается отдельным экраном с кнопкой «Дальше» между ними.

### Одновременная речь двух персонажей

Не склеивать в одну строку. Делать **несколько пассажей подряд** с короткими репликами или цепочкой линков без выбора — так сохраняется ритм и читаемость.

## Служебные команды: строки `//…`

- В тексте, который вы выгружаете из Twine, команда — это **целая строка** в формате **`//что сделать`**: два слеша в начале, затем произвольная инструкция для кода (одной строкой).
- Строка, которая **начинается с** `//`, а дальше непустой текст — **команда**, не реплика.
- Она **не показывается** игроку и **не участвует** в «печатной машинке**.
- Текст после `//` передаётся в **один центральный обработчик** в слое приложения (фон, персонажи, музыка, флаги и т.д.). Неподдержанная команда не должна ломать игру — достаточно предупреждения в консоли.
- Команды на разных языках: либо **одинаковые ключевые слова** во всех локалях, либо в обработчике явно перечислить синонимы по языкам.

Пустая команда (`//` или только пробелы) — игнорировать.

### Фон сцены

- В **начале пассажа** (первые строки тела) задаётся фон командой вида **`//фон имя`** (или синоним вроде `//background name`).
- **`имя`** — базовое имя файла **без расширения**; движок ищет картинку **`имя.png`**, при отсутствии — **`имя.jpg`** (в каталоге фонов проекта).
- Пример: `//фон космос` → файл `космос.png` или `космос.jpg`.
- Команда выполняется **мгновенно** при входе в пассаж или при доходе очереди шагов до этой строки; предыдущий фон заменяется.

### Персонажи на сцене

- Кто **виден** на сцене, задаётся командами, а не только фактом реплики. Пока персонаж не «появился», его портрет **не показывают**, даже если он уже есть в тексте позже.
- **`//показать идентификатор`** (синонимы: `//show`, `//вход`) — добавить персонажа в список присутствующих на сцене и отрисовать его портрет.
- **`//скрыть идентификатор`** (синонимы: `//hide`, `//уход`) — убрать персонажа со сцены.
- **`идентификатор`** совпадает с меткой в репликах (`alien1`, `alien2`, `капитан` и т.д.), регистр не важен.
- При **первой реплике** персонажа, если он ещё не был явно показан командой, движок может **автоматически добавить** его на сцену (удобный запасной вариант для сценариста; явная команда `//показать` предпочтительнее для контроля входа).

## Имена файлов ассетов

Идентификатор в тексте — единственный ключ и для реплик, и для картинок.

### Портреты персонажей

- Префикс реплики **`alien1: …`** → портрет из файла **`alien1.png`** или **`alien1.jpg`** (в каталоге персонажей).
- То же для любого идентификатора: **`капитан: …`** → `капитан.png` / `капитан.jpg`.
- Регистр в диалоге нормализуется к одному виду при поиске файла (как договоритесь в коде, обычно lowercase).
- Если файла нет — не падать: скрытый слот или заглушка + предупреждение в консоли.

### Фоны

- См. команду **`//фон имя`** выше: **`имя.png`** / **`имя.jpg`**.

## Движок диалога (поведение)

- **Базовое правило UX:** в каждый момент на экране **ровно одна реплика** текста (не стопка из двух-трёх абзацев разных героев одновременно). Команды `//…` на экран не выводятся — они выполняются по очереди в том же списке шагов, что и реплики, **мгновенно**, без печати.
- **Кто на сцене:** движок хранит список **присутствующих** персонажей (команды `//показать` / `//скрыть`). На экране видны только они; остальные слоты пусты.
- **Кто говорит:** при показе реплики с префиксом `идентификатор:` этот персонаж получает состояние **«говорит»** (крупнее, ярче, подсветка); остальные **присутствующие** — состояние **«молчит»** (меньше, приглушены). Рассказчик (строка без префикса) — **снять подсветку** со всех портретов, никого не увеличивать.
- **Смена пассажа:** при `renderPassage` список присутствующих можно **сбрасывать** или **сохранять** — зафиксируйте в коде одно поведение; типично сброс, а новый состав и фон задаются командами в начале следующего пассажа.
- Текст появляется **посимвольно** с небольшой задержкой; после **тапа** по «сцене» (но не по кнопкам и полям ввода) текущая строка **допечатывается сразу**.
- Если в пассаже после текущей реплики есть ещё реплики или абзацы того же пассажа, показывается кнопка **«Дальше»** (подпись из локали). По нажатию предыдущая строка снимается, показывается следующая.
- После **последней** реплики пассажа кнопки «Дальше» нет: либо появляются **кнопки выбора** из массива ссылок, либо срабатывает **конец истории** (если ссылок нет).
- Переход по выбору: `renderPassage(имяЦели)` с записью истории для **«Назад»** по пассажам.
- При смене пассажа сбрасывать состояние «конец игры» / формы, если они показываются поверх диалога.

### Устойчивость к переключению языка

Если игрок меняет язык на лету, заново загрузить JSON истории и **перерисовать текущий пассаж** по **тому же имени** пассажа (имена в графе на всех языках должны совпадать; переводятся только `cleanText` и подписи ссылок).

### Доступность

Учитывать `prefers-reduced-motion`: при включённом режиме печать можно делать **мгновенной** (без посимвольной анимации).

## UI и границы ответственности

- **Экран заставки** и **экран игры** — два блока; активный помечается классом; переключение без SPA-фреймворка.
- **Футер** с постоянными ссылками и опциональными контролами (например музыка), строки — из локали.
- **Конец без ветвлений**: отдельная панель (форма, статичный текст и т.д.) показывается колбэком движка «история закончилась»; это не часть Twine, а оболочка приложения.

## Расширение

- Новые команды `//` — только в обработчике команд + кратко в авторской документации для сценариста.
- Новый формат экспорта — в слое парсера; движок диалога по-прежнему получает `{ lines, choices }` на пассаж.

---

Кратко: **в Twine — `//фон …` и `//показать …` в начале сцены, реплики с `идентификатор:`, остальные команды строкой `//…`, одна реплика на экран**; **картинки и фоны — по имени идентификатора** (`alien1.png`, `космос.jpg`); **Twine даёт граф и текст**, парсер — **шаги и выборы**, движок — **фон, состав сцены, очередь реплик, подсветка говорящего, выборы и конец**, локали — **всё, что не сюжет**.
